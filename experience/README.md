# 可复用经验晋升机制

这里保存尚未成熟到可以直接写入长期事实源、但已经值得继续验证的经验候选。它不是任务日志、周报或永久知识库。

## 何时直接更新事实源

满足以下条件时，直接修改最接近的事实源，不创建候选：

- 问题和根因已经明确。
- 改进范围小，能在当前任务内完成并验证。
- 目标位置明确，例如工程契约、工作流、脚本、CI、项目契约或共享测试支持。

## 何时创建候选

以下情况在 `candidates/` 新建一个 Markdown 文件：

- 摩擦已经重复出现，但证据还需要再积累一次。
- 改进跨多个规则或工具，当前任务不适合顺手完成。
- 已经知道问题存在，但目标事实源或最终机制尚未确定。
- 风险较高，需要先记录验证条件再实施。

一次性环境故障、没有证据的猜测、单纯的过程记录和只适用于某个项目的领域知识不进入这里。项目领域经验应留在对应项目仓库。

## 候选格式

从 [`template.md`](./template.md) 复制结构，一个候选对应一个文件。文件名使用 `YYYY-MM-DD-short-slug.md`，正文必须保留模板中的全部二级标题，便于自动检查。

## 晋升与关闭

候选得到足够证据后：

1. 将改进落到最接近的事实源、脚本、CI、共享 fixture 或项目文档。
2. 按候选中的验证方式证明机制实际生效。
3. 删除候选文件；历史由 Git 保存，不维护已完成候选墓地。

若后续证据证明候选判断错误，记录简短原因后删除。候选存在本身不是完成，真正减少下一次的人类介入和重复步骤才算完成。
